# 乒乓闯关王玩法提案

**中文** | [English](GAME_DESIGN.en.md)

本文是待实现、待测试的设计方案。所有角色、球技和关卡举例均为规划内容。

## 定位与主线

竖屏单人乒乓球游戏。玩家从上海开始，挑战各地虚构的民间高手，通过落点和变招制造机会，赢下比赛后学走对方的绝活。

完整主线规划为 18 站，每站 6 关，共 108 关。每站有 3 名电脑对手，名字、打法和招式不同。城市背景使用当地建筑、街区和植物等视觉元素。首发验证范围为 3 座城市、18 关。

## 输入与比赛

手指在球场上滑动，球拍跟随移动。左右追球，向前迎球，向后收拍；对准来球后停在合适位置也能回球。快速前挥增加力量，斜挥改变回球落点。鼠标直接跟随指针，不要求按住按键。

球拍显示在手指上方，减少遮挡。球台和镜头保持固定。普通回球提供适合新手的容错，精准击球提高落点控制。技能强化这些已有动作，不增加额外技能按钮。

热身赛先得 3 分，常规赛先得 5 分，城市决赛先得 7 分。每两分换一次发球；常规赛 4:4、决赛 6:6 时，下一分决定胜负。3 分热身赛同样在 2:2 时进入决胜分。落台、触网、出界和合法回球需要形成统一的判分规则，并通过原型验证。

## 调动与进攻机会

电脑对手有有限移动速度和回位时间。连续打向同一侧会让对手偏移；突然变线，或从长球改成短球，可以逼出勉强救球。高球出现时，玩家向前挥拍完成强力扣杀。

示例回合：两个右侧长球把对手拉开，第三球变成左侧短球；对手扑救后回出高球，玩家扣向空档。

失衡机会必须由左右、长短调动等操作创造，不能仅按成功回球次数充能。扣杀仍然需要合理角度和击球位置，也可能下网或出界。

## 城市高手

每座城市至少有一名有明确招牌动作、破绽和个性表现的冠军。特殊球在出手前有挥拍动作或简短视觉提示，玩家能够根据观察提前准备。

| 城市与虚构角色 | 招牌打法 | 破解方向 |
| --- | --- | --- |
| 上海·弄堂快攻手 | 抢上升期，连续压反手 | 稳住快攻，用长短变化打乱节奏 |
| 北京·胡同削球王 | 低而慢的削球，诱使猛扣下网 | 调整力量，调动位置，等待高球 |
| 成都·茶馆慢球手 | 慢球拖节奏，突然打追身快球 | 观察挥拍动作，提前留出接球空间 |
| 香港·海港侧旋手 | 球落台后向侧面偏转 | 根据旋转提示提前调整位置 |

趣味球拍外观、对手追球动作和观众反应可增强辨识度。装饰效果不能遮住球、球台边界或落点提示。不同城市的难度应来自招式组合和破解要求，而不是只提高球速。

## 学习球技与本站搭配

击败城市冠军，获得金币、经验、外观奖励、护照印章和招牌球技解锁。解锁的球技加入永久球技库。

每站第二关、第四关结束后提供球技三选一。选择的效果持续到本站结束，失败重试保留搭配；进入下一站重新选择。选项中至少保留一项适合当前球拍的强化。

| 球技举例 | 效果方向 |
| --- | --- |
| 借力反击 | 稳定挡住快球后，回球保留更多速度 |
| 近网巧手 | 向后收拍接球时，更容易形成短球 |
| 变线高手 | 连续打向同侧后，下一次斜挥变线更精准 |
| 高球重炮 | 抓住高球向前挥拍，扣杀更有威力 |

数值、触发条件和持续时间由测试确定。先验证基础对打，再加入球技搭配。

## 每站六关

1. 3 分热身赛：熟悉本站球速和操作。
2. 风格对抗：认识本站核心打法，结束后第一次选球技。
3. 特殊规则赛：每场只加一种清楚展示的变化，例如落后开局或有效得分区域。
4. 强敌挑战：组合已有招式，结束后第二次选球技。
5. 30 秒练招：围绕首领招式练习；完成一次即可继续，达标额外奖励。
6. 7 分城市决赛：击败本站冠军，解锁下一城市及冠军球技。

普通关以约一分钟为设计目标，决赛可以更长，实际时间由实机测试调整。主线按关卡顺序开放，星级不阻挡后续城市。

## 成长与重玩

规划 4 种球拍，每种 5 个等级，对应均衡、快攻、旋转和防守方向。升级适度提高控球和容错，操作继续决定比赛结果。完整版本规划 23 种外观，首发先验证 6 款。

护照收集城市奖杯、印章和个人纪录，例如首次逆转、最长精彩回合。训练场免费试用球拍和已开放球技，不记录主线关卡成绩。

后续每日挑战使用固定球拍和固定球技，可免费反复挑战个人最佳成绩。排行榜需要统一配置及成绩校验；续战结果不计入统一配置挑战榜。

## 广告与平台适配

首发只评估两个自愿激励广告位置：胜利结算时额外领取本场金币奖励；城市决赛失败时每场最多一次，撤销刚丢掉的最后一分，从上一比分继续。

不观看广告时可以正常领取基础奖励、继续主线或免费重赛。第一场完整比赛结束前不放商业弹窗，对打过程中不插广告。广告标识、普通领取和重赛入口保持清楚。必须验证广告失败、取消、完成和奖励发放后的恢复行为。

激励广告不得成为正常解锁主线的前提，不以奖励诱导分享。平台规则需要在接入和发布时重新核对：[抖音广告小游戏运营规范](https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/operation1/norms/norms)、[抖音小游戏接入指引](https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/guide/overview)。

皮肤直购留待确认游戏资质、支付准入和账号权限后评估。

## 中英文切换

游戏计划支持简体中文（zh-CN）和 English（en）。首次运行时，系统语言属于中文则使用简体中文，其他情况使用英文；玩家可在设置中切换，选择立即生效并保存在当前设备上。

菜单、操作说明、城市与对手介绍、球技、护照、奖励、广告入口和错误提示都使用可翻译的文案键。切换语言不重置比赛、不改比分和球技搭配，也不重复发放奖励。Canvas 内文字需要同步重绘，素材尽量不内嵌文字。

仓库文档使用独立的中文和英文 Markdown 文件，通过顶部链接切换。具体实现与验证要求见 [中英文支持](LOCALIZATION.md)。这些要求目前尚未实现为游戏功能。

## 程序、素材与存档

计划使用 TypeScript 与 Canvas 2D。比赛计算、输入、绘制、奖励、存档和平台适配分别组织。浏览器版与小游戏版共用比赛逻辑。

比赛状态与绘制对象分离；存档记录已开放关卡、本站球技选择、续战次数和奖励领取状态，处理退出比赛、恢复结算和重复领奖。付费权益和可信排行榜需要服务端支持。

城市素材按需加载。未来生成素材时保存提示词和来源说明；引入第三方素材时核对授权并记录许可证。当前仓库尚无生成美术资产。

## 验证顺序

先验证一场能完整进行、输球后愿意重试的首领战，再扩充城市。观察首次比赛完成率、失败后主动重试率、游玩局数、次日回访，以及广告接入前后这些指标的变化。营收评估使用真实结算和获客、维护成本，不预设收入保证。
